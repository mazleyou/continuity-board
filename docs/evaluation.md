# 품질 평가 가이드

첫 이틀의 모델 검증과 제출용 평가표를 만들 때 쓰는 절차입니다. 아래 수치는 측정 결과가 아니라 **팀이 합의한 목표치**입니다.

## 평가 세트

- 캐릭터 3명 × 장면 6개 = **18컷**. 컷당 후보는 최대 3개까지 만듭니다.
- 18컷 중 **6컷은 수정**까지 실행합니다(의상 색, 소품 교체, 표정 변경 등).
- 범위: 성인 캐릭터 1명, 고정 의상, 단순한 소품, 시각 스타일 1개.
- 다인 상호작용, 복잡한 손동작, 극단적인 옆얼굴은 관찰 사례로만 기록하고 합격 판정에서는 뺍니다.

## 체크리스트 (앱의 “검토 체크리스트”)

평가자 **2명 이상**이 같은 항목을 각자 판정합니다. 항목마다 통과·불합격 중 하나를 고르고, 판정할 수 없는 항목은 비워 둡니다.

| 항목 | 통과 기준 |
|---|---|
| 얼굴 | 기준 얼굴과 같은 사람으로 읽힌다 (나이대, 얼굴형, 눈·코·입의 인상) |
| 헤어 | 길이, 색, 스타일이 기준과 같다 |
| 의상 | 기준 의상의 색과 구성이 유지된다 |
| 소품 | 지정한 소품이 보이고 색과 형태가 맞다 |
| 장면 지시 | 장소, 행동, 표정, 샷 크기가 지시대로다 |

| 수정 지시 (수정 후보만) | 수정 지시대로 바뀌었다 |

수정 컷은 **수정 지시가 반영됐는지**와 **위 캐릭터 기준을 계속 지키는지**를 함께 봅니다. 수정 후보에는 체크리스트에 “수정 지시” 항목이 추가로 나타납니다.

## 합격 목표

- 컷당 최대 3개 후보 안에서 18컷 중 **15컷 이상**이 얼굴·헤어·의상을 통과한다.
- 수정 6건 중 **4건 이상**이 수정 지시와 캐릭터 기준을 모두 만족한다.
- 승인하지 않은 후보가 기존 승인 결과를 덮어쓴 경우가 **0건**이다. `npm test`로 자동 검증합니다.
- 한 컷을 수정한 전후로 다른 승인 이미지의 **파일 해시가 같다**. 앱의 “무결성 확인”과 `npm test`로 검증합니다.
- 외부 사용자 1명이 준비된 환경에서 등록 → 생성 → 수정 → 내보내기를 끝까지 마친다.

## 결과 수집

```bash
npm run report            # data/ 아래 모든 프로젝트 → data/evaluation-report.md, .json
```

보고서는 다음 판정 규칙을 적용합니다.

- **컷:** 생성 후보 중 처음 3개 안에서 얼굴·헤어·의상을 모두 통과한 후보가 있으면 통과입니다. 3개가 모두 불합격이면 불합격, 3개를 다 평가하지 않았고 통과한 후보도 없으면 미평가입니다.
- **수정:** 수정 지시와 얼굴·헤어·의상을 모두 통과해야 통과입니다. 기준 갱신으로 만든 수정은 셈에서 뺍니다.
- **항목 판정:** 한 명 이상이 판정했고 판정한 사람이 모두 통과를 줘야 통과입니다.

보고서에는 평가자 수와 일치도(2명 이상이 판정한 항목 중 판정이 같은 비율), 프리셋·종류·cold/warm별 처리 시간 중앙값, 승인 파일 무결성도 함께 나옵니다.


1. 프로젝트마다 **내보내기 ZIP**을 받습니다. `evaluation.csv`에 후보별 평가자 판정, 소요 시간, 첫 실행 여부, 시드가 들어 있습니다.
2. 처리 시간은 `cold_start = true`인 첫 실행(모델 로딩 포함)과 그 이후 실행을 **나눠서** 보고합니다.
3. 같은 시드로 다시 실행해도 하드웨어나 소프트웨어 버전이 다르면 픽셀이 똑같이 나오지 않을 수 있습니다. 평가표에는 시드만 기록하고, 완전한 재현은 약속하지 않습니다.

## 모델을 바꿔 비교하기 (Distilled ↔ Base)

```bash
WITH_BASE=1 ./scripts/setup-comfyui.sh   # Base 모델 받기 (한 번만)
CB_PRESET=base npm start                 # 20 steps, cfg 5 (공식 Base 템플릿 설정)
```

Base는 Distilled(4 steps)보다 컷당 시간이 몇 배 깁니다. 평가할 때만 쓰고, 기본 제작 흐름은 Distilled로 둡니다.

같은 평가 세트를 두 설정으로 만들어 체크리스트 통과율을 비교합니다. 둘 다 목표에 못 미치면 모델을 더 붙이기 전에 지원 스타일과 장면 범위부터 좁힙니다.
